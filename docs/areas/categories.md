# Categories: names, text keys, adding and deleting

Moved out of the root `CLAUDE.md` in November 2026, word for word except where the pull request that moved it says otherwise. A section name in quotes ("Billing state", "Roles") is a heading in one of the files under `docs/areas/`; the index at the end of the root `CLAUDE.md` says which.

## Categories

These three items belong to "Nothing breaks while the library fills up" (in `docs/areas/library.md`).

- **A category's name, web address, tile picture and place in the list are edited in the Categories panel on `/pulse/videos`** (K1 of the category prompts, decided by Evan on 2026-10-08; schema approved, five additive columns on `CategoryConfig`, migration `20261024180000_add_category_details`). Pulse staff only (`saveCategoryConfigAction`, `requirePulseStaff()` first). An empty box, or one holding exactly today's value, means today's value from `CATEGORY_DEFAULTS` in `lib/categories.ts` and is stored as empty, so a category nobody touched is exactly as it was. **No screen reads `CATEGORY_DEFAULTS` for a name, an address, a picture or the order**: every page, the billing screens, the reports and their CSV files, and the clinic log ask the server for the list, `getCategoryList()` in `lib/db/category-config.ts` (cached for one request), and hand it to client components as props. What still reads `CATEGORY_DEFAULTS` directly is the six starting categories and their fixed order: the rows made on first read, what the pricing engine sells (`CATEGORY_VALUES` in `lib/pricing.ts`) and the stored order of a plan (`inLibraryOrder()` in `lib/access.ts`). The boxes are checked by one pure function both sides use (`readCategoryDetails()`): a name of 1 to 40 characters on one line, an address of lowercase letters, numbers and single hyphens up to 40 (never `search` or `watch`, which are pages of their own under `/library`), a picture that is an https address (the logo rule, `parseLogoUrl()`), a place from 1 to 9999 (the defaults are 10, 20, 30, so 15 goes between the first two). **An address, once a category has had it, stays that category's** (decided by Evan on 2026-10-24: every earlier address keeps working): a new address may not be another category's current, default or earlier one (`takenSlugs()`), checked inside one transaction that locks every `CategoryConfig` row, with the unique column as the last word; the address being left goes into `formerSlugs` (`formerSlugsAfter()`), and `/library/<old address>` (the default one included) redirects to the current one (`findCategoryBySlug()`), as does an old `?add=<old address>` link to Billing. **What a rename changes:** every screen shows the new name at once, plans already bought included (they store the enum value, never the name). **What it does not change:** a clinic log entry keeps the name it was written with (the log is history), and Stripe keeps the words it was given when a subscription was made. New checkouts also send Stripe the STARTING names on purpose (`lib/checkout.ts`): Stripe refuses a repeated request whose words differ from the first, so a rename between a try and a retry would otherwise make the retry fail. The app shell's navigation falls back to the starting names if the list cannot be read, so the shell is still drawn. Adding one is the "+" (see "Adding a category" below).
- **Categories are text** (K2, a non-additive change approved by Evan on 2026-10-24 as a written plan, migrations `20261025020858_categories_as_text` and `20261025021735_category_cast_direction`). The five columns that held the enum `Category` (`Video.category`, `CategoryConfig.category`, `Clinic.categories`, `BillingPlan.categories` and `.entitledCategories`) hold the same words as text, converted in place; no value changed. **The `CategoryConfig` rows are the categories that exist**, and a text column would hold any word, so every place a category arrives checks it with `isKnownCategory()` (or `unknownCategories()`) in `lib/categories.ts`, against `getCategoryList()`: the Pulse forms (video, clinic plan, Categories panel, the videos filter), `npm run db:set-plan`, and the plan writers in `lib/db/billing.ts` (`checkPlanCategories()`, so no accepted plan can name a made-up category; a paid plan that somehow does is applied for its real categories and the clinic log says "Needs a look"). Checkout and plan changes go through the pricing engine, which still sells only the six starting categories (`CATEGORY_VALUES`); K3 decides how an added category is priced. A video's category is also held by a foreign key to `CategoryConfig` (`Video_category_fkey`), so the database itself refuses one in a made-up category. In code, `Category` is `string` (declared in `lib/categories.ts`, no longer from Prisma): the compiler cannot know a list that lives in the database, which is why the check exists. `inLibraryOrder()` keeps a category that is not one of the six (after them, A to Z) instead of dropping it. **Owed: a clean-up migration** that drops the temporary cast (`"Category" AS text`, which let the pre-K2 code keep comparing categories in the minute between the migration and the deploy) and the old `Category` type, once K2 has been live for a while. Until then Prisma's own comparison reports one difference, `DROP TYPE "Category"`, on purpose.
- **Adding a category** (K3, decided by Evan on 2026-10-08; no schema change, a new category is a `CategoryConfig` row): the "+ Add a category" button at the foot of the Categories panel on `/pulse/videos` opens a small form (`AddCategoryForm.tsx`): a name, a web address suggested from the name as it is typed (`suggestSlug()`), an optional https tile picture, an optional place (last when empty). Pulse staff only (`addCategoryAction`, `requirePulseStaff()` first), checked by `readNewCategory()` (the same box rules as a rename; a name or an address any category has or had is refused) and again by `addCategory()` in `lib/db/category-config.ts` under a lock on every category row, so two adds at once make one. The draft is kept on a refusal (`useKeptForm()`). The addition is written to the server log under the staff member's name (categories belong to Pulse, so there is no clinic log for it). Its **key** is made from the name (`suggestKey()`: "Hand & Wrist" is `HAND_WRIST`, a taken key gets `_2`) and never changes, because it is what every plan, video and link stores; the name, the address, the picture and the place are edited like any category's, except that an added category has no starting values, so its name and address cannot be emptied. **A new category starts not for sale** and shows as Coming soon until a video in it is published, by the usual rule (`categoryState()`): a clinic that has it sees a Coming soon row, a clinic without it sees nothing of it. Its **For sale** switch works like any category's (Option A, decided by Evan on 2026-10-26; see Pricing shape): switched on, it is Coming soon until a video in it is published, then for sale on its own and always part of the full library. **A category in use is never deleted**: one with videos, plans or links must never disappear. To retire one, switch it off sale (an added one already is) and unpublish its videos; it then shows nowhere for a clinic without it, and as Coming soon for a clinic that still has it until Pulse takes it off that clinic's plan. There is no "hidden" switch. **The one exception (decided by Evan on 2026-10-26, for a category added by mistake):** an added category that NOTHING uses yet, no video of any kind (published or not), on no clinic's plan and in no accepted plan, has a Delete on its row (two taps: Delete, then "Yes, delete"). `deleteCategoryAction` (Pulse staff only) calls `deleteUnusedCategory()` in `lib/db/category-config.ts`, which refuses the six starting categories outright and, in one transaction holding the category's row FOR UPDATE, checks again that nothing uses it before deleting. Adding a video in it needs that row (its foreign key), and `setClinicPlan()` locks the CategoryConfig rows of the plan it writes FOR SHARE (refusing, with `PlanCategoriesRefusedError`, a category that no longer exists), so a delete and either of those at the same moment end with the category in use and kept, or deleted and the other refused. `listDeletableCategories()` decides which rows show the Delete, as a courtesy.
